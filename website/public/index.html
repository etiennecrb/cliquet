What Cliquet is

Your process, as an app your agents can use safely

A Cliquet app holds your process's data, behind its rules. People use it on its screens, in a browser or in their AI assistant, and agents use its tools over MCP. A release schedule, a service catalog, a household ledger: any process, at work or at home.

  1. Two ways in. Your team opens the app's screens in a browser or on a phone. Your agents call its tools over MCP. Both reach the same actions and queries.
  2. Every change is checked. An action runs in a sandbox with no network, on a copy of the data. The invariants check the result, and a change that breaks a rule is refused with the reason.
  3. Then it's kept. The server commits the checked change to the app's git repository, with who made it and why. Queries only read, so they skip that step.

Questions

What is Cliquet, exactly?

Cliquet builds, deploys and hosts apps that hold a process and its data: a release schedule, a service catalog, a household ledger. Each app has its data, the rules that data must follow, the actions that change it, the queries that read it, and screens for people.

Cliquet runs no AI model and no agent. Your AI assistant writes the app, and your agents use it, wherever they already run: Claude, ChatGPT, Codex, or a script on a schedule. Cliquet is the place they work in, with rules they can't get around.

How is it different from the apps my AI assistant already makes?

An artifact is a page for people, drawn on top of data the assistant can reach. The data stays where it was, and nothing stops the next agent from editing it however it likes.

A Cliquet app holds the data itself. Nothing reaches it except through the app's actions and queries, for people and agents alike. So the rules hold whoever writes, every change is recorded, and every AI assistant your team uses gets the same tools over MCP.

Do I need to code?

No. You tell your AI assistant what you track and the rules it must follow, and hand over your spreadsheet if you have one. The assistant writes the app with Cliquet's builder, which tests every rule against data that breaks it and shows you the screens before anything goes live.

The app is written in Python, so a developer can read and review it. To change it later, you ask again.

Which AI assistants work with it?

Any client that speaks MCP: Claude, ChatGPT, Claude Code, Codex, Cursor and others. You connect your AI assistant once, to your own address, and it reaches every app you may use. An agent that runs on its own gets a token limited to one app and one role.

People without an AI assistant use the app's screens, on a phone or in a browser. Nothing to install.

Who deploys and hosts the apps?

Cliquet does. When your AI assistant publishes an app, it is live on the hosted service, with its own address for people and for agents. There is no server, database, sign-in or deployment for you to set up.

Before a new version goes live, Cliquet checks it against your live data: every rule must still hold. If a change to the data's shape is needed, it runs once, on a copy, and the new code and the migrated data go live together, or not at all.

How is the app's code kept isolated?

An app's code never runs inside Cliquet's server. It runs in a sandbox, a separate virtual machine for each owner, hardened in these ways:

  • No network. Once its packages are installed, the sandbox can reach no host at all. App code can't send your data anywhere.
  • Locked packages. The server resolves an app's libraries, checks each package against its hash, and installs them offline. Only prebuilt packages are allowed, so no package's code runs at install time.
  • No secrets. No key or token of the server ever reaches a sandbox.
  • Limits. Every process that runs app code is bounded in time and file size, and is killed with all its children when it goes past them.
  • A copy, not your data. Each call works on a copy of the data. The server keeps the real data and treats every answer from the sandbox as untrusted: it checks which files changed, their size and their names before it commits anything.
Can an agent break my data?

An agent can only call the app's actions and queries, and only those its role allows. Every action runs on a copy and is checked against every rule before it is kept. A change that breaks a rule is refused with the reason, so the agent can fix its mistake.

For larger jobs, an agent can work in a transaction, which you review on a screen and then keep or drop as a whole. And if a wrong change still gets through, any change can be undone, and the undo is checked against the rules too.

Who can see my data?

Apps are private. Only you and the people you invite can open an app or connect an agent to it, each with a role that decides what they may read and change. An invitation gives nothing until it is accepted.

Each change is recorded with who made it, person or agent, and why. Only the app's owner sees what a change did to the data. API tokens are stored only as a hash, and a token can be limited to one app and one role.

Where does my data live, and can I take it with me?

Each app's data is plain files, such as CSV and JSON, in the app's own git repository, kept by Cliquet's server. Every change is a commit, which makes the history an audit trail you can read and compare.

The owner can download the whole repository, with its history, at any time. Cliquet is open source, so you can also run your own server.
